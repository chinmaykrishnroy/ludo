# Ludo Club v0.1.7

Human turns move automatically when there is exactly one legal token choice,
after the dice animation. Both online and offline games use the same rule. A six
that offers another token or release option still waits for the player; dice
rolling remains manual until its existing 15-second deadline. Automatic choices
are applied by the server online and retain normal captures, bonus rolls and
persist-before-broadcast guarantees.

Dice rolls now use three short, soft taps, distinct from a token's quieter single
tone. Captures can request a brief vibration on supported visible devices after
user interaction. A remembered Capture vibration switch is available in Settings.
Unsupported or blocked vibration has no effect on gameplay. iPhone Safari does
not expose the Vibration API. Reconnect snapshots do not replay capture feedback.

The misleading “It is not your turn” race is fixed. The server checks revision
before turn ownership, returns the authoritative filtered room when resync is
needed, and keeps all turn/deadline checks. The client locks immediately on an
action, submits at most one action for an accepted revision, and honours the
server's animation-ready timestamp. Delayed or duplicate actions no longer
produce an incorrect turn warning. Genuine out-of-turn actions remain rejected.

Reliability work from the engineering backlog:

- Version publication is serialized with queued jobs. Every stable tag retains
  its immutable image/release, while numeric version checks prevent an older
  completion from replacing a newer `latest` alias or GitHub designation.
- Backup verification runs in a bounded worker, removing duplicate synchronous
  scans from the request loop. Integrity/schema checks and the SHA-256 manifest
  are completed before publication. Exclusive links cannot overwrite a recovery
  copy. Failure cleanup, stale staging cleanup, two-copy retention, corruption,
  disk-full simulations and worker timeout have regressions.
- Protected health diagnostics now separate persistence, view preparation,
  commits, backup copy/verify/hash, retention and maintenance timing, plus AI queue
  age. Samples and slow-operation logging are bounded. Unknown API paths return
  JSON 404 responses rather than the application HTML.

The Pi's earlier four-second event-loop peak is documented in
[the runtime investigation](../RUNTIME.md). Instrumentation and moving backup
verification do not establish the cause of that historical peak. Sustained
mixed-traffic capacity testing, accessibility checks and deferred off-host
recovery remain in [TODO.md](../TODO.md).

Validation includes rule/handler regressions, backup fault injection, numeric
release ordering, browser capture feedback/preferences, offline forced movement
and duplicate taps. All normal release gates and both architecture smoke tests
must pass before publication. Physical haptic strength and the new sound balance
still need device/user confirmation.
