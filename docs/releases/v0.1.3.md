# Ludo Club v0.1.3

Voice recordings now finish their audio data before microphone tracks are
released. Empty or unfinished recordings are caught locally, and the server
reports empty audio separately from an oversized upload. Recordings remain
limited to 60 seconds and 1 MiB; the fix does not increase upload limits.

## Reliability and interface changes

- A shared voice controller preserves playback preferences across menus and
  refreshes. Recording sessions serialize finalization, keep cancellation
  sticky, release failed codecs and bound stalled finalization. Escape cancels
  recording without also dismissing its menu.
- Socket.IO reconstruction is bounded to one attachment, with shared ingress
  budgets and an absolute upload deadline before application processing.
- Restricted or full browser storage falls back to memory with a clear notice.
  Startup no longer removes saved games after an unsuccessful read.
- Offline saves use a versioned format and shared semantic validation. Valid
  legacy saves migrate; impossible states and unknown versions are preserved
  without being loaded or silently cleared.
- Archived-room reconnects respect active capacity while retaining the saved
  game and original deadline for a later retry.
- Turn labels use high-contrast dark text, dialogs have explicit accessible
  names, and voice replay buttons have descriptive labels.
- Missing static assets return 404 instead of successful application HTML.

## Distribution and validation

Registry-only Compose instructions and a runtime template no longer require a
source checkout. Privacy text describes configurable voice retention and the
minimum-two-backup policy accurately. The image includes the application MIT
license; generated runtime notices inventory 103 production packages, including
bundled font and icon licenses.

The local unit/integration suite passes 87 tests. CI additionally checks Windows,
Linux, production dependency audits, container startup/restart and browser
regressions in Chromium, Firefox and WebKit. Both AMD64 and ARM64 release images
must pass their image smoke checks before publication.

## Remaining limits

Generated-audio browser tests do not replace checks with real Android/iOS
microphones. The prior shared-host latency stalls remain under investigation;
maximum production concurrency is not established. Off-host backup and alert
automation is deferred. See [TODO.md](../TODO.md) for remaining gates.
