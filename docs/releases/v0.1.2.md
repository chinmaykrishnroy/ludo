# Ludo Club v0.1.2

Bots now take worthwhile captures more often while retaining situational defence and protected-square planning. Captures earn a bounded tactical preference based on opponent progress lost, newly earned bonus rolls and the attacking runner's exposure. A six does not receive the same bonus-roll reward twice. Dice probabilities and human timeout behavior are unchanged.

## Validation

- 68 automated tests and the production build pass locally, including three new capture/defence/bonus-roll regressions.
- In 256 seeded legal positions selected for multiple choices and an available capture, captures increased from 151 to 215 while 41 non-capture choices remained. This measures style, not a general capture rate or proven strength increase.
- All 48 low-budget complete-game smoke simulations finished. The comparison script and measurement file are included; a larger normal-budget strength tournament remains pending.
- The release pipeline checks Linux/Windows, builds and audits dependencies, then smoke-tests both actual AMD64 and ARM64 container images before publishing their manifest.

## Review and remaining work

The release adds [the engineering review](../REVIEW.md) and [prioritized backlog](../TODO.md). The review rates the project 7/10 overall and 6/10 for public production readiness.

**Known security limitation:** incomplete binary-event reconstruction can retain data before application-level budgets apply. Parser-level input limits are the first follow-up fix; this version does not claim that issue is resolved. Browser-storage failures, malformed offline-save recovery, resetting automatic voice-playback preferences and previously measured shared-host latency stalls also remain documented follow-ups. Restrict access to trusted groups while public-production gates remain open.

Images are published at `ghcr.io/chinmaykrishnroy/ludo:v0.1.2`, `:0.1.2` and `:latest` after pipeline verification. Use the digest recorded in the attached image metadata for reproducible deployment and rollback. Retain the existing environment and persistent data when updating.
