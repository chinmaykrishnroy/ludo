# Ludo Club v0.1.15

Ludo Club v0.1.15 resolves live voice mid-speech fallbacks and fixes the stuck
speaking indicator on listener screens.

## Resilient Real-Time Voice Streaming

- **Automatic Speaking Indicator Watchdog & Cleanup**:
  - Added a 3.5-second speaking watchdog on listeners that automatically clears
    the active speaker indicator if network frames stall or abort.
  - Speaking state is unconditionally cleared upon `end`, `abort`, `stopPlayback`,
    `interrupt`, and WebSocket closure.

- **Jitter and Packet Loss Tolerance**:
  - Removed hypersensitive 500ms client timing checks that erroneously treated
    normal speaking pauses and packet arrival gaps as fatal socket errors.
  - Out-of-order and skipped packet sequence numbers are now smoothly handled
    without destroying the live session or disconnecting the client.
  - Audio playback queue catches up to real-time if buffers accumulate rather
    than aborting playback.

- **Buffer Headroom & Encoder Concurrency**:
  - Audio worklet queue tolerance increased from 10 to 50 frames with non-fatal
    frame dropping under severe thread congestion.
  - WebCodecs encode/decode queue limits raised to 32 frames to tolerate
    transient background thread scheduling pauses.
  - Flushed and finish timeouts extended to allow reliable WAN delivery.

- **Fault-Tolerant Server Floor Orchestration**:
  - A single listener disconnect or unreadiness state no longer terminates
    the room's live floor if other listeners remain active.
  - The server drift detection window was widened to 2,000 ms to accommodate
    standard client audio capture packet batching over TCP.
  - Room-wide abort broadcasts ensure all client UI speaking indicators are
    reset synchronously upon session conclusion.
