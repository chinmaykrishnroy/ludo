# Ludo Club v0.1.6

Room communication moves into a dedicated chat overlay opened beside Back in the
game header. A second header button mutes room speakers and game sounds on this
device. The board keeps its existing centred layout.

- Room messages support selectable text, keyboard emoji, uploaded/pasted GIFs,
  quoted replies and player mentions. Emoji-only messages use large unboxed text.
- Type `@` to choose a player; mentions are bold and use that player's token
  colour. Server validation assigns the name/colour from the selected player ID.
- Typing indicators are transient. New messages scroll into view; unread counts
  display 1–9 and `9+`. Replies jump to and highlight the original when retained.
- Swipe the bubble padding to reply; swipe its text to copy. Explicit Reply/Copy
  buttons also support keyboard and pointer users without relying on gestures.
- Inactivity closes the overlay after `CHAT_IDLE_SECONDS`, default 10 seconds.
  Closing preserves a draft for the current room.
- Blocked voice autoplay exposes an actual playback button. The player reuses one
  audio element for iOS gesture unlock and keeps blocked messages available for
  replay. Audio responses support authenticated byte-range requests.
- Muted listeners see a small translucent “player spoke” notice with a direct
  “Unmute to listen” action. These notices never play a sound while muted.
- Voice rate limits allow 30 recordings per guest and 180 per IP per minute;
  separate byte/storage/transport limits remain. Each recording stays capped at
  60 seconds / 1 MiB.

Chat keeps the latest 50 messages with the room. GIF files are limited to 1 MiB
and 2048 pixels per side, stored outside snapshots, protected by room membership
and blocks, and capped at 64 MiB server-wide. Media and messages commit in one
transaction. Dropping a message removes its GIF; room deletion removes its media.
Existing reconnect and voice retention policies are unchanged. Delivery/listening
receipts and delete-after-delivery are not introduced.

Validation includes burst recordings across tabs, blocked audio recovery, media
access and block enforcement, failed-write rollback, emoji and mention editing,
and browser scenarios for chat/replies/GIFs/unread counts/typing/mute/inactivity.
The release pipeline additionally validates actual AMD64 and ARM64 images.

Physical iPhone playback, keyboard/paste behavior and touch gestures still require
device confirmation. Linux WebKit lacks MediaRecorder, so its existing encoder
case checks the unsupported fallback; Chromium and Firefox exercise real codecs.
The hosting, sustained-load, off-host recovery and accessibility work recorded in
[TODO.md](../TODO.md) remains separate from this release.
