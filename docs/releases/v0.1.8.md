# Ludo Club v0.1.8

Header speaker/chat/settings controls now share the same size, style and spacing.
Narrow lobbies wrap safely; bot controls and long names fit their rows. Stars and
entry arrows use the board's SVG coordinates, keeping them centered at every
scale. The tab favicon matches the existing full yellow app icon; PNG install
icons are unchanged.

Dice feedback starts on tap, including when a network response is delayed. The
animation shows cycling pips until the authoritative result arrives, retains the
rolling player's colour while that result settles, then hands over to the next
player with a blank die. It never predicts outcomes or changes server deadlines.
Feedback/presentation ownership is extracted from the main view.

Confirmed quit removes a player's seat and all tokens instead of replacing them
with a bot. Other players retain their tokens and, unless the current player
left, their existing deadline. Below two occupied seats the table returns to the
lobby. Refresh/disconnection preserves the seat: its tokens breathe while the
player is offline, stop on reconnect, and use a steady cue for reduced motion.
Departures no longer count as dice rolls.

Accessibility improvements include caption contrast, dialog keyboard containment
and return focus. Notifications stack so an error cannot cover Unmute to listen.
Browser validation includes geometry, delayed feedback, quit/reconnect, two-theme
WCAG scans and a real two-version PWA update/offline restart preserving saves.

Storage work avoids rewriting unchanged membership rows and separates SQLite
BEGIN/body/COMMIT timings. FULL durability and persist-before-broadcast remain.
A three-minute isolated Delta k3s workload used eight rooms, 16 human clients,
16 bots, backups, valid voice fixtures and reconnects with zero server/AI errors.
Acknowledgement p95 was 16.72 ms and maximum 55.51 ms; both bounded-run targets
passed. Older standalone Pi measurements exposed slow durable commits and are
labelled historical, rather than treated as current cluster performance. See
[RUNTIME.md](../RUNTIME.md) and the remaining [TODO.md](../TODO.md) acceptance items.
Off-host backups/alerts
remain deferred by the owner.
