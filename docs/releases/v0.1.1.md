# Ludo Club v0.1.1

The first versioned container release of Ludo Club, published to GitHub Container Registry for self-hosted Docker, Kubernetes and other container deployments.

## Container images

```sh
docker pull ghcr.io/chinmaykrishnroy/ludo:v0.1.1
docker pull ghcr.io/chinmaykrishnroy/ludo:latest
```

The version image supports **linux/amd64** and **linux/arm64**, including Raspberry Pi. The release workflow tests each architecture image before publishing the version manifest and updating latest. Use the version tag or release digest in GitOps manifests for reproducible deployments and rollback.

The attached image-metadata.json records the exact digest, source commit and platform list. See `deploy/k8s` and `docs/RELEASING.md` for k3s/Argo CD setup. This release does not automatically modify your cluster.

## Included

- Public/private rooms, saved reconnections and server-authoritative 60-second turns.
- Responsive solid-colour board, circular tokens, animated dice/movement and System/Light/Dark themes.
- Remembered random guest names and compact counters with exact-count disclosure.
- Bot levels 0–10, isolated server/browser AI workers and protected-square capture planning.
- Recorded room voice up to 60 seconds / 1 MiB, with microphone permission requested on first use.
- Reporting/blocking, rate limits, transactional SQLite persistence, monitoring and verified backups.
- Eight-room public-list pages, a bounded scroll area and corrected dark-mode contrast.
- Bounded shutdown for unresponsive WebSocket peers, immediate clean-restart lease release, and corrected temporary-port discovery in image checks.

Dice probabilities remain unchanged: independent cryptographic rolls for humans, bots and timeout actions, with no hidden streak protection.

## Validation and known limits

The workflow reruns Linux/Windows tests, builds, production dependency audit and container checks. Each release architecture is smoke-tested for HTTP/PWA assets, real multiplayer, saved-game restart recovery and its compiled AI worker. Architecture digests and anonymous registry access are checked before publication.

The AI was benchmarked in 6,000 seeded games against the previous greedy policy. The user reported successful Android/iPhone gameplay, cross-device voice, refresh and network switching. Recording-limit, denied-permission and installed offline-device checks remain separate acceptance items.

**Known hosting limitation:** testing on the shared Pi showed occasional approximately nine-second room-action pauses despite low typical latency and no AI worker failures. This initial release does not claim resolved host/storage latency or a measured maximum server capacity. See `docs/AI.md` and `docs/DELIVERY.md` for the evidence and limitations.
